# WingmanWM 空间世界模型 — 交接与使用说明

本文档说明**这套世界模型是什么、包含哪些组件、怎么安装与运行、怎么评测、
以及怎么验证交付是完整的**。只描述功能与用法。

---

## 1. 三个仓库的职责

| 位置 | 角色 | 说明 |
|---|---|---|
| `github.com/Hongcheng-Gao/SpatialWorld` | 官方基线运行时（agent + 环境 + 评测框架） | 我们以 `f47b1e0` 为基线，运行时改动全部由 `runtime_overlay/` 提供 |
| `github.com/Sudidaren/wm_for_SpatialWorld`（本仓库） | **WingmanWM 的代码、权重说明、文档与结果** | 世界模型运行时、感知训练代码、评测管线镜像、结果快照都在这里 |
| 本机 `~/spatialworld_eval` | 冻结评测管线 v1.0 与云端编排脚本 | 核心镜像在本仓库 `eval_pipeline/`；编排/监控脚本在 `eval_pipeline/cloud/` |

### 安装（三条命令）

```bash
# 0) 前提：按官方 README 装好 SpatialWorld 环境（venv / AI2-THOR / Linux64 构建）
git clone https://github.com/Hongcheng-Gao/SpatialWorld.git
cd SpatialWorld && git checkout f47b1e0

# 1) 克隆本仓库
git clone git@github.com:Sudidaren/wm_for_SpatialWorld.git lightwm

# 2) 应用运行时 overlay 并校验
bash lightwm/runtime_overlay/setup_lightwm_runtime.sh \
     --repo $(pwd) --overlay lightwm/runtime_overlay

# 3) 一条命令验证交付完整、功能可用、且不含任何模拟器信息通道
bash lightwm/runtime_overlay/verify_delivery.sh \
     --repo $(pwd) --overlay lightwm/runtime_overlay
```

`setup_lightwm_runtime.sh` 把 overlay 覆盖到官方 checkout 上，并逐文件 sha256 校验
（52 个文件）；`verify_delivery.sh` 在此之上再做六项检查（见第 8 节）。
全程不需要 GPU、模拟器、模型权重或网络。

### 感知权重

```bash
export LIGHTWM_STORAGE_ROOT="${LIGHTWM_STORAGE_ROOT:-$PWD}"
python scripts/download_rfdetr.py        # GitHub Release: perception-rfdetr-small-v1
```

权重为 RF-DETR Small 检测头（129 MB）与单目深度头（100 MB），
安装与指标见 [`docs/perception_rfdetr.md`](perception_rfdetr.md)。

## 2. 系统架构

```
环境（AI2-THOR / ProcTHOR）
      │  single-frame RGB image（唯一的视觉输入）
      ├──────────────► MLLM（决策，输出动作）
      │
      └──────────────► WingmanWM
                        ├─ Perception：RF-DETR Small 检测 + DINOv2-S 单目深度
                        ├─ Memory：物体 3D 锚点 / 容器内容 / 手持 / 已访问格
                        ├─ Update：动作日志航位推算 + 地标校正 + 回环纠偏
                        └─ Output：每步一段文本提示，注入在图片之前
                                          │
                                          ▼
                                  ──► MLLM（read-out）
```

**信息边界**：世界模型只使用 RGB 帧与动作日志。它不读取模拟器的实例分割帧、
类别-颜色词表、逐步语义元数据（物体/位置/可见性/物品栏）、真值深度与真值位姿。

### 运行时文件（`runtime_overlay/mllm_base_agent/agent/`）

| 文件 | 功能 |
|---|---|
| `world_model.py` | 世界模型主体：感知融合、锚点记忆、位姿推算与校正、提示输出契约 |
| `self_observation.py` | 由相邻两帧的差异判断动作是否改变了画面（MSE>1），并给出移动/旋转动作集合 |
| `memory_probe.py` | 每步提示块：手持、移动被挡、上一个动作的成败；挂载目标物提示 |
| `target_priority.py` | 目标物位置提示（开关见第 3 节） |
| `object_query.py` | `CheckState()` 完成前状态汇总（开关见第 3 节） |
| `runner.py` | 接线：建世界模型、注入提示、解析 `CheckState`、计量 token 与调用次数 |
| `state.py` | agent 状态定义 |

### 世界模型的能力

| 能力 | 说明 |
|---|---|
| 感知 | 检测框 + 单目深度反投影；同物体多视角最小二乘三角化（基线 ≥0.30 m、最多 10 条射线），与单帧估计按 6:4 融合，σ 随之收敛 |
| 位姿 | 仅由动作日志航位推算；步长严格按 `magnitude → granularity → 0.25 m` 解析；被挡的移动不积分（判定来自画面是否变化） |
| 相机模型 | 相机位于 agent 上方 `CAMERA_Y = 0.675 m`；视线方向由 yaw **与** `cameraHorizon` 共同决定（AI2-THOR 约定：正=下看，限幅 ±60°）；深度按光轴前向距离解算 |
| 地标校正 | 重新观测到的锚点与记忆位置做 Umeyama 相似变换，得到有界的 (Δx, Δz, Δyaw) 修正（尺度须在 ±25% 内、单次 ≤0.5 m / ≤12°） |
| 回环纠偏 | DINOv2 CLS 地点指纹（cos ≥0.985）；要求自该地点起**累计路径 ≥2.0 m** 且相隔 ≥12 步；修正不得超过 `min(1.0 m, 0.35×已走路径)`；8 步冷却；纯平移，位姿、锚点、已访问格一起平移 |
| 因果账本 | 手持物、容器内容、物体状态（开/关、切片、烹饪等），只在"画面确实变化 + 该物体当时可见"时更新 |
| 动作判定 | 若被操作物体从未被感知到、或只在画面边缘露出一条（`edge_px ≤ 5`），该步不给成败结论，只报动作名 |
| 记忆读数 | 每步输出：手持状态、上一步移动是否被挡、上一个动作成败 |
| 持久化 | `world_model_ckpt.json`：原子写入（临时文件 + `os.replace`），含锚点、账本、位姿、俯仰、路径长度与 id 计数 |

## 3. 运行时开关

由 `wm_config_patch.py` 在运行时写入每个任务的配置，全部默认关闭。

| 开关 | 环境变量 | 默认 | 打开后的行为 |
|---|---|---|---|
| 目标物位置提示 | `WM_TARGET_HINT=1` | off | 每步报前 K 个相关物体的位置（见下） |
| 完成前查状态 | `WM_STATE_CHECK=1` | off | 模型可输出 `CheckState()` 获得一次状态汇总 |
| 提示条数上限 | `WM_TARGET_HINT_LIMIT` | 6 | 每步最多几行 |
| 视野内名字上限 | `WM_TARGET_HINT_NAMES` | 5 | 视野内名字行最多几个 |
| 距离阈值 | `WM_TARGET_HINT_MAX_DIST` | 3.0 m | 超过只报方位不报距离 |
| 不确定度阈值 | `WM_TARGET_HINT_MAX_SIGMA` | 0.5 | 超过只报方位 |
| 历史窗口 | `WM_HISTORY_TURNS` | 29 | 近端历史轮数 |
| 历史图降采样 | `WM_HISTORY_MAX_SIZE` | 0（不降） | >0 时历史图转 JPEG 下采样 |
| 调试输出 | `WM_DEBUG=1` | off | 打印世界模型原始输出与异常栈 |

### 目标物位置提示（`WM_TARGET_HINT=1`）

1. 开局向模型调用一次，请它用自己的语言说出任务涉及的物体（自由文本，最多 4 个）；
2. 把这些运行时字符串与检测头**运行时输出的类别名**做大小写/子串匹配，
   只有真正检测到的物体才会有位置；匹配不上时退回用模型自己的说法再匹配一次；
3. 分层配额：任务解析出的目标物 > 手持/容器内容 > 已交互过 > 仅见过；
   若指令谓词已经成立（如"关灯"且账本记为已关闭），该项降权，解析不出谓词则不降权；
4. 渲染规则：当前可见的物体只进"视野内"名字行；位姿未变（未转 ≥15°、未移动 ≥0.25 m）
   时只写"位置同上"；距离/不确定度超阈值则只报方位；模型提过但从未见过的物体只提示一次。

提示里**没有对象词表也没有别名表**；物体名只来自模型自己的表述与检测头的输出。
`tests/test_target_priority.py` 断言该文件不含任何对象名词面量。

### `CheckState()`

第 0 步注入一次协议说明。模型若认为任务接近完成，可输出 `CheckState()`
（`Query(<任意>)` 为等价写法），世界模型把记得的物体位置与状态汇总一次；
汇总只给一次、不每步重复，方位按当前位姿重算。**DONE 不受任何限制**：
任何一步输出 DONE 都直接结束，是否查看汇总完全由模型自己决定。

## 4. 评测协议

| 项 | 值 |
|---|---|
| 任务集 | AI2-THOR 311 条 / ProcTHOR 127 条 |
| 判定 | 冻结 `eval_pipeline` v1.0 |
| TSR | `success / decided`；`failed_external` 记为 Null，不进分母 |
| 每任务步数上限 | 按任务配置（20–80 步） |
| 结果来源 | `runs_local/<批次>/{results.csv,state.json}` |
| 语言/上下文 | `short_term_history_window_size = 29` |

评测入口：

```bash
MODEL_NAME=qwen3vl-8b BASE_URL=http://127.0.0.1:8000/v1 PLAN=off \
  PROFILE=wm RUN_NAME=smoke_wm SCENES=ai2thor WORKERS=1 \
  bash eval_pipeline/run_ablation.sh
```

`PROFILE=llm` 为纯模型基线，`PROFILE=wm` 接入世界模型（`wm_config_patch` 打补丁，
冻结文件逐字节不变）。`eval_pipeline/cloud/` 下有云端编排、监控与配对对比脚本。

## 5. 结果（AI2-THOR 311）

### 配对对比（同任务集逐题，目标物提示关闭）

| 模型 | 判定 | 成功 | TSR | 基线成功 | 基线 TSR | WM 独有 | 基线独有 | McNemar p |
|---|---|---|---|---|---|---|---|---|
| Qwen3-VL-8B-Instruct + WM | 311 | 16 | 5.1% | 6 | 1.9% | 13 | 3 | **0.021** |
| Kimi-VL-A3B-Instruct + WM | 311 | 7 | 2.3% | 6 | 1.9% | 4 | 3 | 1.000 |
| Qwen3-VL-30B-A3B + WM | 311 | 17 | 5.5% | 20 | 6.4% | 4 | 7 | 0.549 |

基线：30B 用 311 条纯模型批次（20 成功 = 6.4%，与官方表格一致）；8B / Kimi 的 438 条批次
原先只有 267/311 有判定，缺的那些在 CloudRendering 下补测后补齐到 311/311（8B 6 成功、Kimi 6 成功）。
配对覆盖全部 311 条，双方都有判定。

### 失败结构

| 模型 + WM | 成功 | 提前 DONE | 步数耗尽 | 其他 | tokens/task |
|---|---|---|---|---|---|
| 8B + WM | 16 | 25 (8%) | 259 (88%) | 284,609 |
| Kimi + WM | 7 | 174 (57%) | 73 (24%) | 162,518 |
| 30B + WM | 17 | 65 (22%) | 206 (70%) | 251,153 |

"提前 DONE" = `fail_reason` 含 `Model claimed DONE but success conditions not met`；
"步数耗尽" = 含 `step limit`。8B 表现为搜索效率不足，Kimi 表现为过早结束。

### 配置对照（AI2-THOR 子集，各 311 条判定）

| 配置 | 成功 | TSR |
|---|---|---|
| WM + 记忆提示（带对象词表的早期配置） | 19 | 6.1% |
| WM（无提示） | 16 | 5.1% |
| 纯模型基线 | 20 | 6.4% |

## 8. 交付验证

```bash
bash lightwm/runtime_overlay/verify_delivery.sh --repo <SpatialWorld> --overlay lightwm/runtime_overlay
```

依次检查：

1. **overlay 完整性**：52 个文件与发布版逐字节一致（sha256）
2. **无冗余文件**：overlay 内每个文件都在 MANIFEST 中登记，MANIFEST 中每个文件都存在
3. **可编译**：`py_compile`
4. **信息隔离审计**（静态）：世界模型路径不得出现模拟器通道
   （`.metadata` / `.controller` / 分割 / 真值深度 / 真值物体表 / 任务真值 / golden 动作 /
   `error_message`），不得 import 环境模块，函数签名不得接收 `env` / `metadata` / `controller`；
   目标物提示文件不得含对象名词面量
5. **功能冒烟**（行为）：用桩感知与桩 VLM 实际跑出——记忆读数、目标物提示
   （默认关、开启后出现位置行）、`CheckState` 汇总只给一次、DONE 不被拦截、
   锚点建立与航位推算、相机模型往返（0/±30/60° 俯仰）、相机高度与竖直符号、
   checkpoint 往返（原子写入）、地标校正有界、回环纠偏触发与拒绝条件、
   手持/容器账本、被挡记录、不可见时不下判定
6. **单元测试**：`CheckState` 7 项、agent 回路 9 项、目标物提示 10 项

仓库级审计（每个被追踪文件必须匹配一条显式规则）：

```bash
python3 tools/audit_repo.py
```

几何精度测量（真值往返，用录制的 episode 数据）：

```bash
python3 tools/eval_projection_accuracy.py \
    --root /mnt/d/lightwm_data_cov --episodes 4 --mode center \
    --runtime <SpatialWorld>/mllm_base_agent/agent/world_model.py
```

输出相机模型与真值的一致性、两套相机模型的 3D/横向/竖向误差对比，以及按俯仰角分组的细分。

## 9. 操作故障排查

| 症状 | 检查 |
|---|---|
| 全部任务恒判失败 | 任务配置里的 `success_conditions`（复数键 + `success_logic`）是否完整 |
| 整批 0 判定、停在 Initialize | 该卡是否设置了 `HEADLESS=1`（weste 必须） |
| 批次不推进 | `cloud_orchestrator_v4.sh` 的"任务已终结"定义；`/root/stopped_arms.txt` 是否含该 run |
| 读取到中间态 | `state.json` 每任务重写，读取需重试 |
| 拉取结果 | `sftp.get /root/autodl-tmp/runs_local/<run>/state.json` |
| 目标物提示无输出 | 该任务配置里 `memory_probe.target_hint.enabled` 是否为 `true` |
| 本地跑测试缺依赖 | 需要 `pydantic` / `requests` / `python-dotenv` / `numpy` / `pillow`；可用 `PY=<python> bash verify_delivery.sh ...` 指定解释器 |

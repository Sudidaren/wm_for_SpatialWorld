## 2. 项目目标与硬约束

### 目标
用 AutoDL 的 RTX 6000D 托管开源 VLM，在 SpatialWorld 家庭任务（AI2-THOR 311 +
ProcTHOR 127）上评测，产出与冻结版 `eval_pipeline` 口径一致、可与官方主表对照的结果，
并把 WingmanWM 做成一个能写进论文的方法贡献。

### 硬约束（`~/AGENTS.md`，接手前务必读）

1. **模型固定**：主模型 = `Qwen3-VL-30B-A3B-Instruct`，**BF16 原版权重，禁止量化**
   （FP8/AWQ/GPTQ 都不行）。另有 Kimi-VL-A3B、Qwen3-VL-8B 作对照臂。
2. **冻结管线 `eval_pipeline` v1.0**：`~/spatialworld_eval/FROZEN.sha256` 覆盖的 19 个
   文件**不得修改**（`config_builder.py` / `eval_config.py` / `supervisor.py` /
   `summarize.py` 等）。**要改运行时行为，一律用运行时打补丁**（`wm_config_patch.py`）
   或新脚本，磁盘上的冻结文件保持逐字节不变。
3. **口径**：`short_term_history_window_size=29`；结果唯一来源
   `runs_local/<批次>/{results.csv,state.json}`；**TSR = success / decided**；
   `failed_model` 计分，`failed_external` 记 Null **不进分母**。
4. **预算**：单次实验总上限 ¥500；超预算自行停机；模型就绪但无任务可跑、空转 >30 分钟自行停机。
5. **汇报节奏**：每阶段（部署/服务就绪/冒烟/每 25 个任务/收尾）汇报一次，固定四段：
   正在做什么 | 进度数字 | 下一步 | 风险。

### 用户最在意的三件事（决定了后面所有设计选择）

1. **绝不能作弊**——反复强调；"基线里没有的东西，WM 臂也不能有"。
2. **诚实**——宁可要负结果也不要包装。
3. **效率**——不要啰嗦、不要节外生枝、只聚焦当前问题。

## 3. WM 架构（当前版 = "无作弊 WM v2"）

### 3.1 数据流

```
环境（AI2-THOR / ProcTHOR）
      │  single-frame RGB image（仅此一条视觉输入）
      ├──────────────► MLLM（VLM 本体，负责决策、输出动作）
      │
      └──────────────► WM
                        ├─ Perception：RF-DETR Small 检测 + DINOv2-S 单目深度
                        ├─ Memory：物体中心 3D 锚点 / 容器内容 / 手持 / 已访问格
                        ├─ Update：纯航位推算位姿 + 地标回环纠偏
                        └─ Output：每步一段文本提示 → 注入在图片前面
                                          │
                                          ▼
                                  ──► MLLM（read-out）
```

**信息隔离（核心卖点）**：WM **不读**模拟器的分割帧、类别-颜色词表、逐步语义元数据
（objects/positions/visibility/inventory）、真值深度、真值位姿。全部来自自己的感知与动作日志。

### 3.2 组件与文件

所有运行时文件都在 `runtime_overlay/mllm_base_agent/agent/`（= 本地
`~/SpatialWorld/mllm_base_agent/agent/`）。

| 文件 | 行数级 | 做什么 | 关键实现点 |
|---|---|---|---|
| `world_model.py` | ~795 | WM 主体 | 见 3.3 |
| `self_observation.py` | ~70 | 帧差判成败 | 相邻两帧 MSE>1 → 动作有效；`MOVE_ACTIONS` 常量在这里定义；替代了旧的 `error_message` 判成败 |
| `memory_probe.py` | ~140 | 每步提示块 | 只输出三件事：**手持 / 移动被挡 / 上一动作成败**；可选接入目标物提示（见 3.4） |
| `target_priority.py` | ~420 | 目标物位置提示（默认关） | 开局让模型自己说物品名（无词表）→ 与检测头输出字符串匹配 → 分层配额 + 位姿触发 + 距离/σ 阈值 |
| `object_query.py` | ~250 | `CheckState()` 完成前查状态（默认关） | 一次性汇总；**不拦 DONE**；通用 `Query(<物体>)` 已砍 |
| `runner.py` | ~900 | 接线与计量 | 每步调用 WM→注入提示；解析 `CheckState()`；记录 tokens/api_calls/步数 |
| `state.py` | | agent 状态 TypedDict | 删掉了 subgoal 相关字段 |

### 3.3 `world_model.py` 内部职责（重点）

| 能力 | 实现位置 | 说明 |
|---|---|---|
| 位姿 | `_resolve_pose` / `_integrate_pose` / `_action_magnitude` | **纯航位推算**：只从动作日志积分。`pose_initial` 必须是 `origin`；`pose_from_action_log=False` 会**直接抛异常**（除非显式设 `LIGHTWM_ALLOW_SIM_POSE=1`，仅限离线测量脚本）。 |
| 移动被挡 | `observe()` 里 `moved is False` → `_blocked_from_moves` | 过去靠模拟器 error_message，现在靠"画面没变化" |
| 感知 | `_perceive_detections` / `_add_view_and_triangulate` / `_unproject` | 检测框 + 单目深度 → 反投影 → 多视角三角化融合成物体锚点；`obj_thr=0.40` |
| 物体槽位 | `_slots` / `_match_or_create_slot` | `objectId → {type, pos, sigma, last_seen, seen, edge_px, box}`；再次看到会精修位置 |
| 因果记忆 | `_contents` / `_holding` / `_update_action_log` | "我把 X 放进了 Y""我手里拿着 X"——只从自己的动作日志推出，不读 inventory 真值 |
| 状态记忆 | `_states` | 由动作+帧差推：`ToggleObjectOn` 且画面变了 → 记为已开启 等。`object_query._STATE_WORDS` 是措辞表 |
| 回环纠偏 | `_maybe_close_loop` / `_apply_drift_correction` | 地点指纹（DINOv2 CLS，L2 归一化）余弦 >0.985 且**真的走远又回来**（≥1.5 m、≥12 步）才接受；修正量必须 <1.0 m 且 <0.35×里程差；8 步冷却。**只做平移**。参数在 `__init__` 里，全部有注释说明为什么这么保守 |
| 输出契约 | `_to_metadata()` | 唯一出口。返回 `{"agent":{position,rotation}, "objects":[{objectType,position,visible,distance,last_seen_step,seen_count,sigma,state,contents}], "inventoryObjects":[...]}` |
| 存盘 | `save()` / `load()` | `world_model_ckpt.json`，`WORLD_MODEL_RESUME=1` 时续跑 |

一个已修的 bug（写在这里免得再踩）：`_to_metadata` 里手持物类型曾经用 `split("|")[0]`，
而感知槽位 id 形如 `det|<Type>|<n>`，于是提示写成"手持：det"。现在是特判 `det` 前缀取第二段。

另一个已修的 bug：`_action_magnitude` 曾经只读 `magnitude`，退化到配置里的
`move_ahead_magnitude=0.5`，导致每一步裸 `MoveAhead`（实际 0.25 m）都按 0.5 m 积分，
里程漂移无界。现在严格复刻 wrapper 的 `magnitude → granularity → move_small_magnitude` 解析。

### 3.4 目标物提示 `target_priority.py`（**默认关**，重点看）

**动机**：模型要找东西，但它不知道东西在哪；WM 其实知道一些。直接把 WM 记忆里的
物体位置报给模型，前提是**不能引入词表**（基线没有词表，用了就算作弊）。

**做法（四步，全程无词表）**：

1. **开局一次额外文本调用**：问模型自己"这个任务要动哪些物体"，自由文本回答
   （`EXTRACTION_PROMPT`，要求输出环境风格的 CamelCase token，最多 4 个）。
2. **匹配**：把模型给的字符串与**检测头运行时输出的类别名**做大小写/子串匹配；
   匹配上的才可能有位置。匹配不上就退回"用模型自己的说法"再匹配一次。
3. **分层配额**（`tier`）：
   - tier 1 = 任务解析出来的目标物
   - tier 2 = 手持物 / 已经在容器内容里
   - tier 3 = 交互过的
   - tier 4 = 只是见过的
   还有谓词降权：如果指令里的动词表明这条已经完成了（`settled_by_predicate`），降一档。
   **谓词解析不出来就不降权**（宁可不降）。
4. **渲染**：
   - 当前**视野内**的物体单独成一行（只报名字，不报坐标，因为"你看得见"）
   - 位姿没变（没转 ≥15°、也没走 ≥0.25 m）时不重复报位置
   - 距离 >`max_dist`(3.0 m) 或 σ >`max_sigma`(0.5) 只报方位不报距离
   - 模型说过但 WM 从没见过 → 只提一次"X：目前没见过"（不重复、不进排名）

**实测解析能力**（在 438 条真实指令上用部署的 30B 跑，0.2 s/次）：
覆盖率 **95.0%**、物品级精确率 **78.4%**、**92.2% 的名字落在检测头标签空间内**。
试过更强的"env + words 双字段"版本，覆盖率反而掉到 93.2%（空回答 1→5），已回退。

**唯一的固定词表是"动词"**（`_ROLE_VERB` / `_DEST_VERB`），用来判断某个记忆项是否已完成，
里面**没有任何物体名**。`tests/test_target_priority.py::test_no_object_vocabulary_in_source`
就是断言这一点。

### 3.5 `CheckState()`（默认关）

- 协议在第 0 步注入一次：模型如果觉得任务做完了，可以先输出 `CheckState()`
  （等价 `Query(all)`），WM 把记得的物体位置与状态汇总给它，模型自判后再决定继续还是 DONE。
- **不拦 DONE**：任何一步输出 DONE 都直接生效，没有任何 gate。
- 只给一次，不每步重复；汇总里的方位是**按当前位姿重算**的。
- 通用 `Query(<物体>)` 按需查询**已砍**（用户：没时间也没心力验证它的收益）。

## 4. 开关总表（⚠️ 这是最容易搞错的地方）

运行时由 `wm_config_patch.py` 把开关写进每个任务的 YAML，**全部默认关**。

| 开关 | 环境变量 | 默认 | 打开后发生什么 | 2026-09-16 三张卡实际状态 |
|---|---|---|---|---|
| 目标物位置提示 | `WM_TARGET_HINT=1` | **off** | 每步报前 K 个相关物体的位置（3.4 节） | **关** |
| 完成前查状态 | `WM_STATE_CHECK=1`（旧名 `WM_QUERY`） | **off** | 模型可 `CheckState()` | **关** |
| 提示条数上限 | `WM_TARGET_HINT_LIMIT` | 6 | 每步最多几行 | 关时无意义 |
| 名字行上限 | `WM_TARGET_HINT_NAMES` | 5 | 视野内名字行最多几个 | 关时无意义 |
| 距离阈值 | `WM_TARGET_HINT_MAX_DIST` | 3.0 m | 超过只报方位 | 关时无意义 |
| 不确定度阈值 | `WM_TARGET_HINT_MAX_SIGMA` | 0.5 | 超过只报方位 | 关时无意义 |
| 历史窗口 | `WM_HISTORY_TURNS` | 29 | 覆盖冻结配置的近端历史轮数 | 29（两边一致） |
| 历史图降采样 | `WM_HISTORY_MAX_SIDE` | 0（不降） | >0 时转 JPEG 下采样 | 0 |
| WM 调试 | `WM_DEBUG=1` | off | 打 raw_meta 与异常栈 | off |
| 步耗时 | `WM_STEP_TIMING=1` | off | 打印每步耗时 | off |

### ✅ 怎么判断某个批次到底开没开

**不要靠读代码猜，直接读云端生成的任务配置**：

```bash
ssh <卡> "grep -A8 'target_hint\|object_query\|plan:' \
  /root/autodl-tmp/runs_local/<run_name>/task_configs/task_configs/<task_id>.yaml"
```

2026-09-16 22:50 实测（三张卡全部一样）：

```yaml
memory_probe:
  enabled: true
  world_model:
    enabled: true            # ← WM 本体：开着
  plan:
  object_query:
    enabled: false           # ← CheckState：关
  target_hint:
    enabled: false           # ← 目标物位置提示：关（用户看到这条才放心）
```

### 为什么这一轮全关

先测**纯 WM 底数**（只给记忆、不给任何提示），把收益归因干净；
提示类机制都做成独立开关，等底数清楚了再逐个加进来做消融。
**所以"WM 臂收益很低"这个结论，对应的是"没有目标物提示的 WM"，不是完整版。**

## 8. 踩过的坑（照抄，别再踩）

1. **`pkill -f` 会自杀**——命令串里出现匹配模式就把自己杀掉。**一律写进脚本文件再执行**，
   模式用 `[t]hor` 这种括号技巧。（踩过 3 次）
2. **weste 必须 `HEADLESS=1`**：否则 `config_builder` 不设 `env.platform=CloudRendering`，
   ai2thor 默认走 Linux64，而这张卡没有该构建 → 开始 16 KB/s 下载 769 MB，
   97 分钟 0 判定。Linux64 构建已从本地上传补齐（1005 MB），但 `HEADLESS=1` 仍必须带。
3. **`state.json` 每个任务都会重写**：读取要重试，否则会读到中间态，出现假的"进度回退"告警。
4. **cqa1 上没装 `xdpyinfo`**：健康检查要用"进程在 + X socket 可连"，别用 `xdpyinfo`。
5. **本机 Python 是 externally-managed**：`pymupdf` / `cairosvg` 装在 `/tmp/pdfvenv` 和
   `/tmp/vecenv`；跑仓库里的三个单测需要一个带 `python-dotenv` / `pydantic` / `requests` 的解释器
   （本地缺，可 `python3 -m venv /tmp/wmtest && /tmp/wmtest/bin/pip install python-dotenv pydantic requests`）。
6. **`success_conditions` 复数键**：官方 evaluator 读复数键 + `success_logic`；
   只给单数键会走 legacy 分支对 list 调 `.get()` 抛异常 → **所有任务恒判失败**。
   已在 `scripts/*/work/run_task.py` 里归一化。
7. **结果回拉**：`sftp.get /root/autodl-tmp/runs_local/<run>/state.json` → `~/wm_dev/`。
8. **`json.dump` 是增量写的**：`world_model.save()` 曾经把带 numpy 的 slot 直接丢给
   `json.dump`，序列化到一半抛 `TypeError: Object of type ndarray is not JSON
   serializable`，于是**留下半个文件**——三张卡上 14/14 个 `world_model_ckpt.json`
   全是截断的。不影响判分（checkpoint 只在开了 `resume` 时被读，且异常被捕获），
   但文件本身永远是坏的。2026-09-16 已修：先 `_jsonable()` 转换，再
   `写 .tmp + os.replace` 原子替换。**凡是写 JSON 快照的地方都要按这个模式写。**

唯一依赖是官方 SpatialWorld 环境里的 Python 包（`pydantic` / `requests` /
`python-dotenv` / `numpy`）——本地跑时用 `PY=<python> bash verify_delivery.sh ...`
指定解释器即可。

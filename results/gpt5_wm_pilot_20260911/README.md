# GPT-5 与 WM+GPT-5：已封存的小样本配对评测

这是 2026-09-11 封存的历史试验：选定 20 个任务，17 对获得双方完成／失败结果，另外 3 个 WM 任务因 API 额度耗尽中断。按用户要求保持停止。
**WM 使用旧 OWLv2 检测＋DINO 单目深度（177,720,649 参数），不是新发布的 RF-DETR Small。新感知模型加 GPT-5 的任务成功率尚未测出。**

## 成功率

| 环境 | 完成配对数 | GPT-5 | WM+GPT-5 | 差值 |
|---|---:|---:|---:|---:|
| AI2-THOR | 10 | 2/10（20.0%） | 7/10（70.0%） | +50.0 个百分点 |
| ProcTHOR | 7 | 0/7（0.0%） | 0/7（0.0%） | 0.0 个百分点 |
| **合计** | **17** | **2/17（11.8%）** | **7/17（41.2%）** | **+29.4 个百分点** |

WM 多成功 5 个任务，没有出现 GPT 成功而 WM 失败的配对。精确双侧 McNemar p=0.0625，样本量不足以给出确定的提升结论。

## 成本

| 同一任务的 WM 减 GPT 平均差值 | AI2-THOR（10 对） | ProcTHOR（7 对） | 合计（17 对） |
|---|---:|---:|---:|
| 总 token | −42,935.5 | +161,755.0 | +41,348.8 |
| 耗时 | −67.7 s | +254.1 s | +64.8 s |

这些是原始完成尝试的累计用量及任务耗时，不是单次模型调用成本。中断尝试的 token 未知，没有算入；整体不能声称节省 token 或时间。双方均成功的任务中，GPT 步数减 WM 步数平均为 −1，即 WM 平均多走一步。

## 解释边界

1. 这是项目内的阶段性诊断，不是完整 SpatialWorld benchmark，也不是后来冻结评测管线的全量重跑。任务从选择时已经完成的基线任务中抽取，并非从完整 benchmark 均匀抽样；基线结果原样复用。
2. AI2-THOR 的 10 个场景中，8 个属于感知训练划分、2 个属于验证划分，没有感知测试划分。不能用本表声称未见场景上的任务泛化。
3. 当时 ProcTHOR wrapper 会把某些被拒绝的交互替换为成功的 Pass。两组均受到影响，WM 还可能据错误反馈更新手持状态；保留原结果，没有用后续修复重写成绩。
4. 历史 WM 配置为 `done_gate=False`、`pose_from_action_log=True`、`pose_initial=origin`。当前 GitHub 默认配置与历史配置可能不同，不能用当前默认设置代替当时配置来解释这批结果。
5. 17 对完成任务与全部 20 个入选任务的统计分母不同。完整 20 个基线任务是 2/20 成功；公平配对表使用双方均有结果的 17 个任务，不能把 2/20 与 7/17 直接比较。

RF-DETR 的离线检测 F1／精确率／小物体召回率见[感知模块文档](../../docs/perception_rfdetr.md)，它们与本页的任务成功率属于不同实验。
